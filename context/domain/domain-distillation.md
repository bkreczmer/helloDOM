# Domain distillation: helloDOM

## Summary

helloDOM łączy właściciela nieruchomości z agentem. Właściciel zapisuje ofertę (miasto, typ, cena), system liczy każdemu agentowi wynik 0–100 według stałej reguły i pokazuje do trzech najlepiej dopasowanych, a właściciel zaprasza jednego z nich. Agent przyjmuje albo odrzuca zaproszenie, a status oferty idzie za tym cyklem.

Rdzeń (Core) to dwie poddomeny:

- **dopasowanie**: wynik i ranking;
- **cykl oferty i zaproszenia**: statusy, jedno aktywne zaproszenie, odpowiedź.

Kod mówi językiem dokumentów prawie słowo w słowo i egzekwuje niemal wszystkie reguły w bazie: checki, RLS, granty kolumn, 3 funkcje RPC i trigger. 22 terminy Core i Supporting mają miejsce w kodzie, a tylko 1 jest **missing in code**: uzasadnienie wyniku, świadomie odłożone. Najmocniejszy rozjazd to stan „szkic”. PRD opisuje go jako pierwszy status oferty i warunek edycji, a kod celowo go nie osiąga. Decyzja zapadła w zmianie owner-offer-management, ale PRD nie poprawiono.

**#1 rankingu to cel „właściciel rozumie, dlaczego agent dostał dany wynik”.** To kryterium sukcesu produktu w poddomenie Core, którego żaden kod nie realizuje (FR-013 odłożone jako nice-to-have).

Rozjazdy według strony naprawy: kod 0, dokumentacja 4, decyzja 3. Otwarte pytania: 6.
